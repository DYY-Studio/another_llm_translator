# Another LLM Translator 最小产品规范

本文是 Another LLM Translator 稳定产品语义和核心不变量的唯一权威文档。它回答“产品保证什么”，不定义命令参数、配置字段、存储 schema、Prompt wire format 或代码模块。

- 使用方法与用户可观察行为见[用户指南](USER_GUIDE.md)。
- LLM Adapter、Document Adapter、Preset 和插件协议见[Adapter 契约](ADAPTERS.md)。
- 实现模块、依赖方向和持久化职责见[模块职责](MODULES.md)。
- 开发、测试和打包见[开发指南](DEVELOPMENT.md)。
- 尚未实现的方向和进入条件见[产品路线图](ROADMAP.md)。

## 1. 目标与边界

### 1.1 产品目标

产品面向长文档和可恢复的本地翻译工作流，最小闭环为：

1. 导入一个或多个文档。
2. 整理并发布术语。
3. 分阶段生成翻译、校对建议和润色建议。
4. 由用户明确应用建议。
5. 按原文件边界导出目标文本或双语结果。

所有模型阶段都必须支持有限并发、限速、重试、取消、诊断和中断后继续。模型输出只有在通过结构和阶段校验后才能成为可用结果。

### 1.2 产品边界

- 项目是自包含的工作边界；不同项目互不共享进度和阶段结果。
- Web、桌面壳和 CLI 使用同一套项目数据与执行语义。
- 应用面向单机和可信局域网，不是远程、多用户或公网服务。
- Document Adapter 决定可导入和可重建的文档格式；宿主不提供任意格式互转。
- 模型结果不构成质量保证，最终内容需要人工审阅。

### 1.3 非目标

当前产品不承诺：

- 分布式执行、消息队列、网络共享盘协调或同一项目的并发写入合并。
- 自动 Provider 判断、静默切换端点或 Provider fallback。
- 远程插件、自动安装、插件市场或插件沙箱。
- 无人工确认的术语冲突裁决、建议应用或历史结果替换。
- 自动翻译质量评分。
- 源 Segment 的增量编辑和任意格式的字节级往返。
- PDF、DOCX、Markdown 等未由已安装 Document Adapter 声明支持的格式。
- 面向未来版本的通用兼容层或迁移框架。

未来方向及其进入条件只在[产品路线图](ROADMAP.md)记录。

## 2. 核心领域模型

### 2.1 Project

Project 保存一组输入文件、项目设置、Prompt、术语、阶段结果、运行记录和导出文件。项目目录是完整边界；打开外部项目不会移动它，删除项目则删除整个项目边界内的数据。

项目创建后，全局默认值和全局模板不会静默覆盖项目副本。用户必须显式同步或保存更改。

### 2.2 File

File 是源文档、选择、排序和导出的边界。

- 一个项目可以包含多个、甚至不同格式的 File。
- File 顺序决定浏览、范围选择、处理和导出顺序。
- 重排 File 不改变其身份，也不删除已有结果。
- 从项目移除 File 后，其历史记录仍可用于审计，但不再参与当前进度、复用、术语匹配或导出。
- 替换 File 是一次受控的重新导入。系统只复用能够确定对应的内容；新增、修改或无法唯一确认的内容从未完成状态开始。替换前必须向用户展示影响并取得确认。

File 可以由 Document Adapter 划分为若干 part。part 是文档内部的内容边界，不替代 File 的选择和导出职责。

### 2.3 Segment

Segment 是持久化内容单元，也是进度和恢复的唯一单位。

- 每个 Segment 属于一个 File 和一个 part，并在当前 File 中有稳定顺序。
- 术语、翻译、校对、润色和应用结果都绑定 Segment。
- 模型请求如何分组不能改变 Segment 的身份或长期进度。
- 空白 Segment 保留在源数据和导出顺序中，但不发送给模型，也不要求阶段结果。
- 非空 Segment 的连续前导空白以源文为准。模型结果写入和导出时恢复该前缀；正文内部和尾随空白不由宿主猜测修复。

Document Adapter 可以向模型提供不同于用户可见源文的受控表示，但不得改变持久化的 Segment 边界或使结果无法安全映射回原文。具体协议由[Adapter 契约](ADAPTERS.md)定义。

### 2.4 Chunk

Chunk 是一次模型请求的临时分组，不是持久业务状态。

- Chunk 只包含当前范围内仍需处理的非空 Segment。
- 分组必须保持源文顺序，并遵守 File 和 part 的内容边界。
- Token 限制、调度方式、重试或上下文拆分可以改变 Chunk，但不能改变 Segment 进度。
- 不得使用 Chunk ID、Chunk 数量或历史 Chunk 组成推断完成状态或恢复位置。

### 2.5 Run

Run 是一次阶段执行记录。

- Run 记录阶段、范围、开始与结束状态、实际设置快照和执行摘要。
- Run 可以完成、失败、中断，或在用户明确选择后继续。
- 继续旧 Run 时保留其身份和原始范围，只处理该范围内尚无可用结果的 Segment。
- Run 是审计和续作边界，不替代 Segment 级进度。
- 不调用模型的应用操作也可记录 Run，但不得伪造模型、Prompt 或请求信息。

## 3. 进度、结果与用户决策

### 3.1 进度状态

阶段对当前活动 Segment 只呈现三种进度：

- `pending`：没有成功结果，也没有最近失败结果。
- `completed`：至少存在一条成功结果。
- `failed`：没有成功结果，且最近一次尝试失败。

`pending` 由缺少结果推导。缺少上游结果是阶段启动条件不满足，不额外建立长期 `blocked` 状态。设置变化产生警告和选择，不建立自动 `stale` 状态。

### 3.2 当前结果选择

- 当前可用结果是该 Segment 未被重置的最新成功结果，而不是最近写入的任意记录。
- 一次强制重做失败不会销毁此前的成功结果；失败仍应在诊断中可见。
- 人工重置会屏蔽对应阶段此前的成功结果，但不删除历史记录。
- 重置校对或润色时，同时重置该阶段已应用结果；不级联删除其他阶段。
- 阶段运行默认复用已有成功结果，只处理未完成和失败内容。重做已完成内容必须由用户明确选择。

### 3.3 设置变化

影响阶段语义的 Prompt、模型、Preset、Adapter、目标语言、上下文、术语版本或校验规则发生变化时：

- 已有成功结果继续可见，不被自动清空、隐藏或判定无效。
- 启动阶段前必须明确提示存在混合设置。
- 用户选择复用时，只处理尚未完成的内容；新旧设置结果可以并存。
- 用户选择重做时，只重做明确选定的范围。
- 非交互运行必须通过显式参数表达同样的决定，不能替用户猜测。

设置差异的具体计算和存储属于实现，不是跨版本公共协议。

### 3.4 未完成 Run

发现同阶段未完成 Run 时，交互用户必须选择继续或结束旧 Run 后新建。非交互入口必须显式表达该选择。

- 继续使用旧 Run 的原始范围，但使用当前明确生效的连接和阶段设置处理未完成内容。
- 新建 Run 不得把旧 Run 伪装成已完成。
- 同阶段多个遗留 Run 只保留一个明确的续作候选，其余标记为已中断。
- `run-all` 不隐式续作某个子阶段 Run；它按各阶段当前结果决定是否继续流程。

## 4. 输入、项目变更与导出

### 4.1 导入

- 输入必须由已安装的 Document Adapter 明确支持；扩展名冲突或显式 Adapter 不匹配时直接失败。
- 导入按用户给定顺序或确定性的目录顺序建立 File 顺序。
- 原始输入复制到项目边界内，后续执行不依赖外部源文件继续存在。
- 解码失败、结构不安全、Adapter 缺失或状态无法读取时明确失败，不使用有损替换解码或其他格式回落。
- 空项目允许创建和配置，但模型阶段与导出在没有可处理内容时应在创建 Run 前失败。

具体格式、选项和安全限制由相应 Document Adapter 契约定义，用户操作见[用户指南](USER_GUIDE.md)。

### 4.2 文件变更

- 添加、移除、替换或重排 File 必须在项目写锁内原子提交。
- 项目存在运行中写任务时，不允许改变 File 集合或顺序。
- 文件变更失败不得留下部分更新。
- 替换前必须预览可复用、需重做和无法确定的内容；确认后才写入。
- 移除或替换不会自动删除历史 Run、阶段结果、术语或既有导出。
- 已发布术语不会因源文件变化而自动删除；用户需重新扫描或编辑。

### 4.3 导出

- 用户明确选择结果阶段、File 范围、单语或双语，以及来源格式或统一 TXT。
- 每个 File 独立导出，不把多个 File 静默合并。
- 来源格式导出由原 Document Adapter 重建；统一 TXT 由内置 TXT Adapter 处理。
- 缺少所选阶段结果、Adapter 能力不足、状态损坏或目标路径非法时，当前导出失败；不自动改用 TXT。
- Document Adapter 只能写入受控暂存区。全部文件生成并校验成功后，结果才移动到正式输出位置。
- 模型生成的标记不得未经 Adapter 校验直接作为任意 HTML 或文档结构写入。

## 5. 阶段语义

### 5.1 术语

术语阶段从源文生成候选，候选必须经过发布才成为翻译、校对和润色使用的术语库。

- 扫描和导入与人工编辑合并时，人工决定优先。
- 冲突不得静默裁决。
- 用户移除的术语保持禁用，重新扫描不会自动恢复。
- 没有已发布术语时允许直接翻译，但必须醒目警告。
- 术语导入必须在完整校验后整体合并，缺失条目不表示删除现有术语。

自动术语决策只生成可审阅草案，不直接修改术语库。应用、拒绝、丢弃、替换和撤销都必须是显式用户操作。

### 5.2 内容概括（实验）

内容概括是术语页中的实验能力，不属于稳定核心工作流。

- 用户按 Document Adapter 提供的 File/part 边界选择参与范围；系统不猜测章节。
- 参与选择只影响概括，不缩小术语扫描范围，也不会让普通术语入口、CLI 或 `run-all` 自动生成概括。
- 已成功的片段结果可以在后续运行中复用；源文或生成条件变化时必须显示可理解的过期或不可验证警告。
- 完整概括由用户显式聚合。单个片段已完整覆盖边界时可以直接采用；多个片段按原文顺序聚合，超限时允许递归压缩，但不得截断输入。
- 每个边界独立成功或失败。一个边界失败不回滚其他边界已经发布的结果。
- 历史结果可以保留和查看；清理不能删除仍被保留结果依赖的内容，也不能因无法验证而静默删除。
- Markdown 导出有独立范围选择，并包含可追溯的原文引用。

该能力的当前操作方式见[用户指南](USER_GUIDE.md)，后续稳定门槛见[产品路线图](ROADMAP.md)。

### 5.3 翻译

- 翻译以 Segment 为单位保存完整目标文本。
- 请求可以携带有限的同边界上文、已发布术语和用户启用的有效概括；参考内容不属于本次进度，也不要求模型返回。
- 模型响应必须能够无歧义映射到本次请求的 Segment；不得按返回顺序猜测缺失或未知项。
- 结构完整但映射集合不一致时，整批响应不可信；结构中断时只保留已经完整解析且校验通过的独立结果。
- 启用的翻译校验在结果成为成功结果前执行。修复预算耗尽后的失败或警告行为必须由配置明确决定。
- 建议级校验最多触发一次定向修复；仍未满足时可以保留译文，但必须记录 warning。

### 5.4 校对

- 校对以当前可用翻译为基准。
- 所选范围存在缺少翻译的非空 Segment 时，整个阶段在创建 Run 前失败。
- 每条成功结果只表达“接受当前基准”或“提供完整建议文本与原因”。
- 生成校对建议不覆盖翻译。
- 结果记录其基准；基准变化后，旧建议仍可见，但应用前必须提示或拒绝。

### 5.5 润色

- 润色优先使用已应用校对，其次使用当前翻译。
- 所选范围存在缺少可用基准的非空 Segment 时，整个阶段在创建 Run 前失败。
- 润色与校对使用相同的“接受/建议”语义，不自动覆盖基准。

### 5.6 应用建议

- 应用是独立结果，不覆盖翻译或建议历史。
- 接受项采用生成建议时的基准文本；建议项采用完整建议文本。
- 应用前必须确认建议基准仍是当前基准。基准已变化时默认拒绝；用户可以显式允许应用旧基准，并留下警告记录。
- 所选范围缺少建议或基准时，整个应用操作失败，不应用可用子集。

### 5.7 完整流程

完整流程依次执行术语、翻译、校对建议和润色建议，不隐式应用校对或润色。

- 已发布且可复用的阶段结果不会重复生成。
- 任一阶段未完成时，不启动依赖它的后续阶段。
- 设置差异仍需逐阶段由用户决定是否复用。
- 因为不隐式应用校对，完整流程中的润色默认以翻译为基准。

## 6. 执行与恢复不变量

### 6.1 Token 与上下文

- 请求必须在模型输入能力内；估算不确定时留出安全余量。
- Chunk 可以继续拆分，但单个超长 Segment 只有在能够无歧义重组时才允许拆分。
- 无法安全拆分的单个 Segment 直接失败，不截断、不跳过、不改用其他模型。
- 上文和术语需要计入同一请求预算；减小上下文必须遵守明确的阶段规则，不能静默删除业务必需输入。

### 6.2 并发、限速与重试

- 并发和速率限制按实际生效的 Preset 与密钥执行。
- 网络、超时和明确可重试的 HTTP 错误可以在有限预算内重试。
- 认证、配置、协议和不可恢复的客户端错误应立即失败。
- 任何重试都必须保留取消能力，并在最终诊断中说明尝试结果。
- 流式响应中断或协议错误时丢弃未完成聚合，不保存半成品；重试可能造成重复计费，用户必须能够知晓。
- 不允许从流式静默回退到非流式，也不允许切换 Provider。

### 6.3 持久化与中断

- 阶段结果按 Segment 独立提交；成功结果不因同批其他结果失败而丢失，除非整批响应无法可靠映射。
- 项目写入必须在单项目写锁内保持一致。
- 取消和进程中断后，已经提交的成功结果继续可用，未完成内容可再次执行。
- Run 在所有工作结束或明确取消后才收尾；进程异常留下的 Run 必须在下次进入时明确处理。
- 存储损坏、版本不支持或必需状态缺失时直接失败，不自动构造兼容数据。

### 6.4 日志与敏感数据

- 普通日志不得记录完整 Prompt、源文、鉴权 Header、API Key 或未脱敏请求正文。
- API Key 只从明确配置的环境变量或系统钥匙串读取，不写入项目、Preset、Run 快照或日志。
- Debug 记录可能包含完整请求、响应和源文；启用前必须让用户知晓风险。
- 可信 Python 插件与宿主同进程运行，不提供沙箱；安装即表示信任。

## 7. 用户界面与入口一致性

- Web 是主要交互界面；桌面壳承载同一 Web 工作台并提供原生文件选择能力。
- CLI 与 Web 共用项目、阶段、锁、限速和恢复语义，不得形成第二套业务规则。
- Web 页面刷新可以重新发现当前进程仍在运行的任务；进程重启后不承诺恢复 UI 任务句柄，但持久化结果和 Run 仍在。
- 项目存在运行中任务时，仍允许读取概览、术语、阶段结果和任务进度；读取、刷新和项目切换不触发项目修复。
- 同一项目同时只允许一个写任务；冲突操作明确失败。
- Prompt 补齐和 SQLite 升级属于显式项目修复，运行中项目必须在任务结束或取消后执行。
- 所有会复用旧结果、重做结果、应用建议、替换文件、删除项目、发布部分术语或暴露局域网服务的操作，都必须在用户可见的位置明确确认。
- 不支持的配置、协议、运行环境或输入格式必须给出明确错误，不猜测、不自动修复、不静默兼容。

## 8. 最小验收基线

一个发布版本至少应满足：

1. 多 File 项目按确定顺序导入、选择、处理并分别导出。
2. File、Segment、Chunk 和 Run 的职责不混淆；进度只由 Segment 结果决定。
3. 设置变化不会清空历史，复用与重做由用户明确选择。
4. 术语冲突和自动决策草案不会未经批准修改发布库。
5. 校对和润色只生成建议，应用是独立且显式的操作。
6. 取消、失败和重启后已提交结果仍可用，未完成内容可继续。
7. 不可恢复的输入、协议、存储或配置错误会明确失败，不发生静默回落。
8. 普通日志和持久化快照不保存 API Key 或未脱敏敏感请求。
9. 各入口使用相同业务语义；Web 不复制后端进度或恢复算法。
10. Adapter 与插件行为符合 [Adapter 契约](ADAPTERS.md)，而不是由本文件重复定义。
