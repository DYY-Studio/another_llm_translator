# 产品路线图

本文只记录尚未实现的方向、进入条件和暂缓原因。已经实现的产品行为见
[最小产品规范](MINIMAL.md)与[用户指南](USER_GUIDE.md)；协议现状见
[Adapter 契约](ADAPTERS.md)。完成项不在这里保留第二份规格。

路线图不是承诺日期。每个方向只有满足进入条件后才进入设计与实施。

## 1. 桌面平台

### Windows Tauri 公开 Beta

**下一步**：验证 Windows bundled Python runtime、Credential Manager、Unicode/长路径、安装包签名和完整安装、
升级、卸载流程。

**进入条件**：有可持续验证的 Windows 构建环境和代表性安装测试机器；Web 与桌面共享的业务行为在
Windows 上无需复制业务分支。

**公开 Beta 门槛**：签名安装包可重复构建，外部项目与用户数据保留行为经过验证；只有用户开启
局域网共享时才请求必要的防火墙权限。

**暂缓项**：自动更新、Windows 专属业务实现和未经验证的企业部署能力。当前先证明安装与核心
工作流可靠，避免同时扩大分发和产品边界。

### Linux Tauri Beta

**下一步**：先确定目标发行版、包格式及 Wayland/X11 支持范围，再验证 bundled Python runtime、Secret Service、
文件权限和局域网共享。

**进入条件**：选定可维护的发行版矩阵，并具备对应 CI 或测试机器。缺少 Secret Service 时必须
形成明确的凭据使用规则，不能保存明文密钥。

**Beta 门槛**：目标平台的安装、启动、凭据、项目路径和卸载后数据保留均有可复现验证。

**暂缓原因**：在平台矩阵未确定前发布会形成无法兑现的兼容承诺。

## 2. 当前实验的下一步

### 内容概括

内容概括目前仍是术语页中的实验能力。已实现操作和结果语义不在路线图复述，见
[用户指南](USER_GUIDE.md)与[最小产品规范](MINIMAL.md)。

**下一步**：用代表性材料观察边界覆盖、原文引用、失败恢复、历史结果提示和人工可用性；收集
用户是否需要独立入口的真实反馈。

**进入稳定功能的条件**：

- 不同 Document Adapter 的内容边界和原文追溯已得到实际验证。
- 用户能够理解片段、完整结果、过期提示和重新生成的区别。
- 失败、取消、源文变化与继续执行没有重复或遗漏。
- 质量可通过明确的人工检查清单评价，而不是依赖随机分数。
- 独立入口或继续留在术语页的选择有真实使用证据。

**暂缓项**：章节识别、章节编辑器、独立 Labs 工作区和通用辅助工具框架。当前通用 File/part
边界足以验证需求，尚无证据支持更大的内容模型。

## 3. 协议成熟度

功能可用不表示协议已经稳定。协议字段和当前版本只在[Adapter 契约](ADAPTERS.md)定义。

### 声明式 JSON LLM Adapter

**下一步**：继续用真实端点验证现有声明能力。只有出现当前 JSON 请求/响应/SSE 规则无法表达
且具有持续需求的端点，才考虑扩展 schema。

**稳定条件**：至少两个真实、持续维护且行为不同的实现通过统一契约和端到端测试；版本范围、
迁移、废弃周期、配置差异和插件缺失行为都有明确规则。

**暂缓原因**：先扩展 schema 会把供应商偶发现象固化为长期公共接口。

### Document Adapter 与可信 Python 插件

**下一步**：继续用 EPUB、SRT 和一个独立第三方风格 Adapter 验证导入、替换、原格式导出、版本
读取和插件缺失行为。

**稳定条件**：TXT、EPUB 与至少一个真实外部 Document Adapter 持续通过统一契约；出现第二个
外部维护者后，再决定长期兼容范围和插件分发策略。

**暂缓项**：远程插件、自动安装、在线市场和沙箱。当前插件是可信同进程扩展，尚无足够需求
承担分发、隔离和安全模型的复杂度。插件依赖运行时状态及后续平台评估见
[插件依赖运行时](#插件依赖运行时)。

### 插件依赖运行时

Web wheel/venv 与 macOS bundled Python runtime 的纯 Python/二进制依赖探针和统一运行时迁移已完成。
当前构建、验证、用户可见行为、模块边界和插件契约分别见[开发指南](DEVELOPMENT.md)、
[用户指南](USER_GUIDE.md)、[模块职责](MODULES.md)与[Adapter 契约](ADAPTERS.md)。

**后续方向**：Windows 与 Linux 是否采用相同 managed runtime，随各自桌面平台路线进入实施评估；
进入条件见[Windows Beta](#windows-tauri-公开-beta)和[Linux Beta](#linux-tauri-beta)。

### Python LLM Adapter

**进入条件**：出现至少一个声明式 JSON POST 无法表达、且确实需要支持的真实端点；随后由第二个
独立实现共同验证公共边界。

**预期最小职责**：只在规范化模型请求与宿主 HTTP 请求规格之间转换，并把宿主取得的响应转换为
规范正文或错误；HTTP Client、密钥、限速、重试、Run 和持久化仍由宿主拥有。

**暂缓原因**：当前声明式 Adapter 已覆盖现有端点。在真实缺口出现前定义 Python 方法签名或动态
加载器只会制造未经验证的兼容承诺。

### 通用稳定门槛

任何协议标记为稳定前都必须满足：

- 至少两个真实且持续维护的实现。
- 统一契约测试和端到端测试通过。
- 配置变化、结果复用、插件缺失和版本升级行为明确。
- 支持版本范围、兼容政策和废弃周期已经记录。

## 4. 候选 Labs

| 方向 | 进入条件 | 暂缓原因 |
| --- | --- | --- |
| 多角度评价 | 章节定位和原文追溯已经验证，并选定一个具体评价角度 | 当前概括不能默认支撑所有评价，过早抽象会形成无依据的工作流 |
| Ruby 注音 | 有明确日语阅读需求和代表性样本 | 需要先独立验证正文保真、注音位置、专名、歧义和已有注音处理 |

新增 Labs 功能应优先复用现有模型调用、Preset、凭据、限流、取消和诊断能力。只有至少两个真实
用例共享同一成果模型时，才提炼新的公共实现。

## 5. 明确不规划

当前不规划：

- 远程插件、多语言进程协议、在线市场、自动插件安装或插件沙箱。
- 自动 Provider 判断、静默 fallback 或通用工作流引擎。
- 通用 DOM、排版树或任意格式互转。
- 公网服务、多账号权限、远程遥测或 TLS 托管。
- 桌面端独立业务后端或迁移到 Electron。

若真实需求改变这些判断，应先在本路线图补充进入条件，再单独设计。
